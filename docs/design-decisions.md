# 設計方針 — v0.2 に向けた決定事項

grill セッションで確定した設計判断の記録です。19の分岐をすべて解決した結果をまとめています。

## ライブラリの再定義

**article-system は「記事を書く側」に提供する道具である。**

これが今回いちばん大きな軌道修正でした。従来のドキュメントは読者向けの記事表示ライブラリとして書かれていましたが、実態としての価値は執筆側にあります。マークダウンを書いて記事にするまでの一連の流れ — 書く、確認する、検証する、md として取り出す — を丸ごと引き受け、複数のプロジェクトで毎回作り直さずに済ませることが目的です。

読者向けの表示コンポーネント（`ArticleList` / `ArticleDetail`）は引き続き提供しますが、これらは「Studio のプレビューが本番と一致することを保証する」ための土台という位置づけに変わります。

## 1. スタイルとクラス設計

### 決定

デフォルトCSSを `styles.css` として同梱し、**それ単体で公開に耐える完成度**まで作り込みます。記事のタイポグラフィ（見出し階層・行間・余白）、リスト・表・引用・コードブロック、一覧のグリッド、Studio の2ペイン、レスポンシブまで含みます。

クラスの付き方は「常時付与＋追記」です。

```
classNames 未指定:            <h2 class="as-heading">
classNames={{heading:"my-h"}}: <h2 class="as-heading my-h">
```

### なぜこの形か

`styles.css` の `import` を利用側が任意にできる点が効いています。**読み込まなければ `as-` クラスは無害なただの文字列**になるため、「デフォルトを使う」と「今までどおり全部自分で書く」の両方が、同じコードで成立します。Tailwind のユーティリティクラスもそのまま追記で効きます。

### 解決される問題

新しいプロジェクトで必要な記述が激減します。

```tsx
// これまで（ArticleDetail の classNames だけで20行超）
<ArticleDetail article={a} classNames={{ wrapper: "...", dateYear: "...", /* 12個続く */ }} />
// さらに ul / table / blockquote 用の CSS を子孫セレクタで自力で書く

// これから
import "@fififuchun/article-system/styles.css";
<ArticleDetail article={a} />
```

## 2. 見出しタグを正しいものに戻す

現在 `##` `###` `####` はすべて `<div>` として出力されています。ブラウザ標準スタイルの打ち消しを利用側にさせないための判断でしたが、**ライブラリがCSSを持つと決めた時点でこの理由は消滅しました**。リセットはライブラリ側で当てられます。

```tsx
// Before
h2: ({ children }) => <div className={classNames.heading}>{children}</div>,

// After
h2: ({ children }) => <h2 className={cx("as-heading", classNames.heading)}>{children}</h2>,
```

これによりスクリーンリーダーの見出しジャンプと検索エンジンの文書構造認識が回復します。将来「目次の自動生成」を入れる際の土台にもなります。

## 3. ArticleStudio

### 接続

```tsx
<Route path="/article/preview" element={<ArticleStudio />} />
```

### レイアウト

```
PC（左右2ペイン）                    スマホ（上下2ペイン）
┌─編集────────┬─プレビュー──┐        ┌─編集──────────┐
│ ---        │ [詳細][一覧]│        │ ---           │
│ title: ... │             │        │ title: ...    │
│ ---        │  2026       │        ├───────────────┤
│            │  8/19       │        │ [詳細][一覧]  │
│ ## 見出し   │  記事タイトル│        │  2026 8/19    │
│ 本文...     │  ────────  │        │  記事タイトル   │
│            │  見出し      │        │  ────────     │
├────────────┤  本文...     │        │  見出し        │
│⚠ 警告       │             │        └───────────────┘
├────────────┤             │
│[本番DL][下書きDL]         │
└────────────┴─────────────┘
```

### 編集ペイン

生の md を1枚の textarea で編集します。フォーム化しないことで、エディタとのコピーペーストが自由に行き来でき、ファイルの中身と1:1が保たれます。

### プレビューペイン

`ArticleDetail`（詳細）と `ArticleList` に1件だけ渡したもの（一覧カード）をタブで切り替えます。**タイトルの折り返しやサムネイルのトリミングは詳細プレビューでは絶対に気づけない**ため、書く段階で両方確認できるようにします。

`ArticleDetail` をそのまま再利用することで、プレビューと本番の一致が構造的に保証されます。

### 内部設計（既存記事編集を見越す）

v1 は新規作成専用ですが、状態を「白紙から書く」ではなく**「編集中の記事」**としてモデル化します。`articles` を任意で受け取れる形にしておけば、既存記事編集は「初期値を白紙ではなく既存記事にする」だけで実現できます。

```tsx
interface ArticleStudioProps {
  articles?: Article[];   // v1 では未使用。将来の編集機能で使う
  imageBasePath?: string;
  classNames?: ArticleStudioClassNames;
  articleClassNames?: ArticleDetailClassNames;
}
```

**v1 の制約**: `articles` を知らないため、日付衝突の警告（後述）は出せません。ただし日付の初期値が常に今日である以上、実際に踏む確率は低いままです。

## 4. 検証

### ルール

| 検出内容 | 例 | 起きること |
| --- | --- | --- |
| 必須項目の欠落 | `latestUpdate` がない | `0年undefined月undefined日` と表示される |
| キー名の typo | `lastUpdate` と書いた | 同上。無言で通過する |
| 日付の形式違反 | `date: 2026/08/19` | ソートが壊れ `id` の採番まで連鎖して崩れる |
| 引用符付きの値 | `title: "記事"` | 引用符ごと値に入る |
| フロントマターの閉じ忘れ | `---` が片方だけ | 全文が本文として扱われる |
| 更新日が投稿日より前 | `latestUpdate < date` | 論理矛盾 |
| 未登録の画像を参照 | ドロップしていない画像 | 本番で壊れた画像になる |
| 日付衝突（将来） | 既存記事より古い日付 | 既存記事のURLがずれる |

### 厳しさ

**警告がゼロでなければ本番ダウンロードはできません。** 壊れた記事がリポジトリに入る経路を完全に塞ぎます。

### 実装方針

バリデータは**独立した部品として切り出し、Studio と `createArticles` の両方で共有**します。書いている最中と記事化した後で、同じ基準が効きます。

```
validateArticle(raw: string) → Issue[]
   ├─ ArticleStudio    … 警告表示、ダウンロードの可否判定
   └─ createArticles   … ビルド時に console.warn
```

## 5. 下書きの保全

検証を厳格にした結果、「とりあえずダウンロードして退避」ができなくなりました。現在の `ArticlePreview` は `useState` だけで状態を持ちリロードで消えるため、**このままでは長文執筆中の事故が損失に直結します**。

二段構えで守ります。

1. **localStorage への自動保存** — 入力のたびに保存し、次に開いたとき自動復帰。ボタンを押す必要がないので保存忘れが原理的に起きない
2. **下書きダウンロード（別ボタン）** — 検証を通らなくても md として出せる

### 下書きの印

下書きダウンロードで出る md は定義上**検証を通っていない壊れた記事**です。`src/articles/` に置かれた瞬間に本番へ出てしまうため、システムが読み取れる印を付けます。

**ファイル名の `_` 接頭辞**を採用します。

```
src/articles/
  _2026-08-19-書きかけの記事.md   ← 除外される
  2026-08-18-夏の更新.md          ← 公開される
```

**除外の責任はライブラリが持ちます。** 現在 `createArticles` は `Object.values()` でファイルパスを捨てていますが、`Object.entries()` に変えることでライブラリ自身がファイル名を見て `_` 始まりを除外できます。

```ts
// 利用側の glob は変更不要
import.meta.glob("../articles/*.md", { query: "?raw", import: "default", eager: true })
```

利用側が除外パターンを書く必要がないため、書き忘れる余地がありません。

## 6. 画像

### 決定

ドラッグ&ドロップで仮登録します。放り込んだ画像はブラウザ内だけの一時URLでプレビューに即反映され、md には**ファイル名だけ**が入ります。ダウンロード時に「この画像を `public/article_imgs/` に置いてください」と一覧で提示します。

### 解決される問題

本番の Studio で新しい記事を書くとき、参照する画像はまだリポジトリに存在しません。従来はプレビューに必ず壊れた画像アイコンが出て、**記事の顔であるサムネイルを確認できないまま書く**ことになっていました。

### 将来への接続

GitHub コミット機能を入れるとき、**md と画像を同じコミットに載せる**流れへそのまま伸ばせます。

### 併せて直す既知の欠陥

- `thumbnail` が空でも `<img src="/article_imgs/">` が無条件に描画される → 未指定なら描画しない
- `imageBasePath` が単純な文字列結合のため `![](https://example.com/a.png)` が `/article_imgs/https://...` になる → 絶対URLは素通しする

## 7. 記事の識別子

`date` 昇順の index を据え置きます。

### 既知のリスクと対処

古い日付の記事を後から追加すると、以降の `id` がすべてずれて公開済みURLが別の記事を指します。

```
初期状態:              後から 2024-01-01 の記事を追加:
id=0  2024-03-15        id=0  2024-01-01  ← 新規記事
id=1  2024-08-20        id=1  2024-03-15  ← /blog/0 だった記事
id=2  2025-01-10        id=2  2024-08-20  ← /blog/1 だった記事
```

**対処は運用をデフォルト動作で強制すること**です。Studio が `date` と `latestUpdate` の初期値を常に今日にすれば、新しい記事は必ず末尾に追加され、既存の `id` はずれません。

残るリスクは2ケースだけです。過去の日付を意図的に指定したとき、既存記事の `date` を後から直したとき。これらは既存記事編集機能を入れる段階で、日付衝突の警告として拾います。

## 8. ファイル名規則

日付とタイトルを自動連結します。

```
2026-08-19-はじめての記事.md
_2026-08-19-書きかけの記事.md   ← 下書き
```

識別子は index なので**ファイル名はURLに影響しません**。要件は「フォルダを見て中身が分かること」と「既存ファイルと衝突しないこと」の2点です。同じ名前を置くと既存記事が黙って上書きされるため、タイトルを含めて衝突しにくくします。

### 実装上の手当て

日本語ファイル名は OS 間の移動や git で問題を起こしうるため、以下を入れます。

- ファイルシステムで使えない文字（`/ \ : * ? " < > |`）の除去
- 空白のハイフン化
- 長すぎる場合の切り詰め

## 9. アイコン

幅広いアイコンセットとして提供します。記事系（時計・人・タグ）と Studio 系（ダウンロード・画像・警告・閉じる）に加え、矢印や外部リンクなども揃えます。

**named export のまま個別に出す**ことで、使わないアイコンは利用側のバンドルから tree-shaking で落ちます。数が増えてもバンドルサイズには影響しません。

外部のアイコンライブラリには依存しません。現在の依存は react-markdown 系の3つだけで、それも `external` 指定でバンドルから外しています。この軽さを保ちます。

## 10. 配布方法

**現状の `npm link` では利用側プロジェクトをデプロイできません。** README が案内する `npm link` もデモの `file:../` も、ローカルのファイルシステム上のパスを指す仕組みで、Vercel や Netlify のビルド環境には存在しないためです。「Studio を本番サイトに常設する」と決めた以上、ここは変更が必須でした。

```bash
npm i github:fififuchun/article-system
npm i github:fififuchun/article-system#v0.2.0   # タグで固定
```

`ce86c36「distもビルドに含める」` で成果物がリポジトリに入っているため、追加のビルド設定なしにそのまま動きます。

### 運用上の注意

この方式では **`dist` のコミット忘れが即座に利用側の不具合になります**。`src` を直して `npm run build` を忘れると、GitHub 上のコードと配布物がズレたまま各プロジェクトに配られます。pre-commit フックでビルド成果物の同期を機械的に強制します。

### 併せて直す

`package.json` の `exports` に `./styles.css` を追加します。また `types` は記述順にマッチするため先頭へ移します。

```json
"exports": {
  ".": { "types": "./dist/index.d.ts", "import": "./dist/index.js" },
  "./styles.css": "./dist/styles.css"
}
```

## 11. 秘匿

**ライブラリは認証を一切持ちません。** 利用側がルート登録を条件分岐すれば済むためです。

```tsx
{import.meta.env.VITE_STUDIO === "1" && (
  <Route path="/article/preview" element={<ArticleStudio />} />
)}
```

`renderLink` でルーターを利用側に委ねてきた設計と一貫しています。ただし将来 GitHub コミット機能を載せた時点で、ここは書き込み可能な入口に変わります。**その段階ではホスティング側の認証（Vercel Deployment Protection など）が実質的に必須**になる点を README に明記します。

## 併せて修正する既知の欠陥

grill の過程で前提が変わり、直せるようになったものです。

### `<p>` の中に `<div>` が入る問題

マークダウンでは画像だけの行も段落として扱われるため、現在の出力は不正な入れ子になっています。

```html
<div class="article-paragraph">
  <p><div class="article-image"><img></div></p>   ← p の中に div
</div>
```

CSRでは動きますが、React 開発モードで `validateDOMNesting` 警告が出ます。SSR に持ち込むとブラウザが `<p>` を自動で閉じ、ハイドレーションエラーになります。

CSSを自前で持つと決めたため、**段落のラッパーを1段にして解消**できます。画像は `<p>` でラップしません。

### その他

| 項目 | 対処 |
| --- | --- |
| `thumbnail` 未指定でも `<img>` が出る | 未指定なら描画しない |
| 外部URLの画像が使えない | 絶対URLは `imageBasePath` を前置せず素通し |
| `date` が不正だとソート順が不定 | バリデータで検出。`NaN` 比較を避ける実装に変更 |
| `subsubheading` が README にない | ドキュメント更新 |
| テスト・Lint・CI がない | `parseFrontmatter` / `createArticles` / バリデータにユニットテストを置く |

## 実装の順序

依存関係を考えると、この順で進めるのが最短です。

1. **バリデータの切り出しとテスト** — Studio と `createArticles` の両方が依存するため最初に必要
2. **`createArticles` の改修** — `Object.entries()` 化、`_` 接頭辞の除外、不正な日付の扱い
3. **表示コンポーネントの修正** — 見出しタグ、`<p>` の入れ子、画像パス、`as-` クラスの付与
4. **`styles.css` の作成** — 3が終わっていないとクラス構造が固まらない
5. **アイコンセット** — 4と並行可能
6. **`ArticleStudio`** — 上記すべてに依存する
7. **配布まわり** — `exports` 追加、pre-commit フック、README 全面改訂
