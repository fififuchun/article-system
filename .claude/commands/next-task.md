`docs/tasks.md` の未完了タスクを **1件だけ** 進めてください。

## 手順

1. `docs/tasks.md` を読み、`- [ ]` が付いた**いちばん上のタスク1件**を対象にする。それ以外のタスクには着手しない
2. 対象タスクが参照している `docs/spec.md` の章を読む。仕様はすべて spec が持っている
3. 実装する
4. `npm test && npm run build` を実行する
5. `src/` を変更したなら、ビルド後の `dist/` もステージに含める（spec §12。コミット忘れが利用側の不具合になる）
6. `docs/tasks.md` の対象タスクを `- [x]` に変える
7. 実装・`dist/`・`docs/tasks.md` を**1つのコミット**にまとめる

## 完了の条件

`npm test && npm run build` が通ること。通らないうちはチェックを付けず、コミットもしない。

タスク名に **（テスト → 実装 → グリーン）** とある場合は、テストを先に書いて落ちることを確かめ、実装して通すところまでが1件分の作業です。テストだけ書いて終わらせない。

## 止まる条件

次のいずれかに当たったら、**作業を中断して何が起きたかを報告**してください。無理に進めない。

- spec に書かれていない判断が必要になった（推測で実装しない）
- ゲートの失敗を3回直しても通らない
- 対象タスクが、前のタスクの未完了部分に依存していて着手できない
- `- [ ]` が1件も残っていない（「全タスク完了」と報告して終了）

## 制約

- `docs/spec.md` §16「意図的に受け入れている制約」は**直さない**。バグに見えても仕様
- 対象タスクに関係ないファイルは触らない。ついでの修正をしない
- テストを消したり `it.skip` にしてゲートを通さない

## 報告

最後に次の3行だけを出す。

```
完了: <対象タスク名>
ゲート: npm test <結果> / npm run build <結果>
次: <次の未完了タスク名>
```
